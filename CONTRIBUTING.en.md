# Contributing to pylzt

Python 3.12+, managed by [uv](https://docs.astral.sh/uv/).

## Setup

```bash
git clone https://github.com/open-lzt/pylzt && cd pylzt
uv sync --extra dev
git config core.hooksPath .githooks   # local ruff+mypy+pytest gate on push
```

## The gate

`.github/workflows/ci.yml` runs on every push and PR:

```bash
uv run ruff check src tests
uv run mypy
uv run pytest -q
```

`.githooks/pre-push` mirrors it locally so red is caught before the push. Don't bypass it.

E2E tests hit the live API, need `LZT_E2E_TOKEN` and are excluded by default — `uv run pytest -m e2e -q`.

## Generated code

Methods, response models, enums and facades under `src/pylzt/{methods,models,enums,facades}/` are generated from the OpenAPI spec and carry a `Generated by forge — DO NOT EDIT` docstring. A regen wipes hand edits.

Change the generator or the hand-patch mechanism instead — see [`docs/codegen-runbook.md`](docs/codegen-runbook.md). Regenerate with `python -m dev.codegen build`, and commit the updated `dev/generated/openapi/*.json` alongside the codegen diff.

If a signature changes, update [`docs/integration-guide.md`](docs/integration-guide.md) in the same PR.

## Releasing (maintainers)

Publishing is tag-driven — `.github/workflows/release.yml` builds sdist and wheel, runs the gate, publishes to PyPI over OIDC trusted publishing (no token in secrets) and cuts a GitHub Release with generated notes.

1. Bump `version` in `pyproject.toml`. Semver: bugfixes → patch, new endpoints or options → minor, a changed public signature → major.
2. Commit the bump.
3. Tag and push:

```bash
git tag v0.2.1 && git push origin main v0.2.1
```

The tag must match the `pyproject.toml` version. PyPI refuses to overwrite an existing version, so a mismatched or reused tag fails at the publish step, after the build already passed.

`-rc`, `-alpha` or `-beta` in the tag marks the GitHub Release as a prerelease.

## Pull requests

PRs go against `main`. Keep one logical change per PR, and add a test for new behaviour.
